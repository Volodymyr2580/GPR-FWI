# MPI GPR FWI 内存优化解决方案

## 问题分析

您遇到的错误是：
```
prterun noticed that process rank 9 with PID 3987949 on node ubuntu exited on signal 9 (Killed).
```

**信号9 (SIGKILL) 通常表示系统内存不足**，操作系统强制终止了进程以防止系统崩溃。

## 内存使用分析

根据代码分析，主要内存消耗来源：

1. **波场数据存储**：每个shot需要存储 `(1000+20) × (1000+20) × 8000` 个float64值
   - 单个shot波场数据：~7.6 GB
   - 50个shots：~380 GB（这是导致内存不足的主要原因）

2. **模型数据**：1000×1000的模型数组相对较小
3. **观测数据**：50×8000的数组，内存需求较小

## 解决方案

### 1. 内存监控功能
- 添加了实时内存监控，显示进程和系统内存使用情况
- 在每个关键步骤输出内存状态
- 自动检测可用内存并给出警告

### 2. 内存优化策略
- **减少波场数据保存**：只在第一个epoch保存波场数据用于调试
- **智能内存管理**：在不保存波场数据时立即清理相关变量
- **垃圾回收**：在关键位置强制进行垃圾回收

### 3. 运行建议

#### 方案1：减少MPI进程数
```bash
# 根据系统内存选择进程数
mpirun -n 4 python main.py    # 8GB内存
mpirun -n 2 python main.py    # 4GB内存  
python main.py                # 内存不足时使用串行
```

#### 方案2：使用内存监控脚本
```bash
python memory_monitor.py      # 分析内存需求
./run_with_memory_check.sh    # 自动选择最佳配置
```

#### 方案3：修改参数（如果必要）
在 `main.py` 中调整：
- 减少时间步数：`steps = 4000`  # 从8000减少到4000
- 减少网格大小：`xl, zl = 500, 500`  # 从1000减少到500
- 减少炮点数量：`source_list = [(0, i) for i in range(0, zl, 4)]`  # 增加间隔

## 修改的文件

1. **main.py**：添加内存监控和优化
2. **forward.py**：添加内存监控
3. **memory_monitor.py**：内存分析工具
4. **run_with_memory_check.sh**：智能运行脚本

## 使用方法

1. **运行内存分析**：
   ```bash
   python memory_monitor.py
   ```

2. **使用优化版本**：
   ```bash
   mpirun -n 4 python main.py
   ```

3. **监控运行过程**：
   程序会自动输出内存使用情况，如：
   ```
   [内存监控 Epoch 1 开始] 进程内存使用: 2048.3 MB (2.00 GB)
   [系统内存] 总内存: 16.0 GB, 可用: 8.2 GB, 使用率: 48.7%
   ```

## 预期效果

- **内存使用减少**：从~380GB降低到~2-4GB
- **稳定性提升**：避免因内存不足导致的进程被杀死
- **可监控性**：实时了解内存使用情况，便于调优

## 注意事项

1. 减少波场数据保存会影响梯度计算的效率（需要重新正演）
2. 如果仍有内存问题，建议进一步减少模型大小或时间步数
3. 建议在运行前先使用内存监控脚本评估需求

## 故障排除

如果仍然遇到内存问题：
1. 检查系统是否有足够的可用内存
2. 尝试更少的MPI进程数
3. 考虑使用更小的模型进行测试
4. 检查是否有其他程序占用大量内存
