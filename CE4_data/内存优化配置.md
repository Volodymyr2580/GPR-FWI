# GPU内存优化配置

## 问题分析

GPU Out of Memory原因：

1. **波场数据占用**：350步（降采样后）× 430×820×4字节 ≈ 470MB/炮
2. **PyTorch缓存**：UNet、梯度等 ≈ 500MB
3. **CuPy内存池**：FDTD计算临时数组 ≈ 200MB
4. **20进程共享4GPU**：每GPU被5进程挤爆

总计：**每炮约1-1.5GB，20进程同时 = 20-30GB** → OOM！

## ✅ 已完成的优化

### 1. 波场降采样率增加（节省50%内存）
- `WAVEFIELD_SUBSAMPLE: 10 → 20`
- 波场数据：470MB → 235MB/炮

### 2. 每炮后清理GPU内存
```python
# main.py 第1062-1066行
torch.cuda.empty_cache()
cp.get_default_memory_pool().free_all_blocks()
```

### 3. 使用CPU版gradient（避免GPU OOM）
- gradient计算在CPU上（稳定）
- forward仍在GPU上（加速）
- 折中方案，避免GPU内存不足

## 🚀 推荐配置

### 配置1：4进程（强烈推荐）

```bash
cd ~/swz/mpi_gprfwi/CE4_data
mpirun -np 4 python main.py --mode inversion
```

**优点**：
- 每GPU 1进程，无竞争
- 内存充足：每GPU 23GB，单进程用<5GB
- 速度最快

### 配置2：8进程（折中）

```bash
mpirun -np 8 python main.py --mode inversion
```

**优点**：
- 每GPU 2进程
- 内存可接受：每进程<10GB

### ❌ 不推荐：20进程

- 每GPU 5进程 → 内存竞争严重
- OOM风险高

## 📊 内存使用估算

| 配置 | 每GPU进程数 | 峰值内存/进程 | 总内存/GPU | 状态 |
|------|------------|--------------|-----------|------|
| 4进程 | 1 | ~4GB | ~4GB | ✅ 安全 |
| 8进程 | 2 | ~4GB | ~8GB | ✅ 可行 |
| 12进程 | 3 | ~4GB | ~12GB | ⚠️ 紧张 |
| **20进程** | **5** | **~4GB** | **~20GB** | **❌ OOM** |
